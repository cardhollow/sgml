1. What is SGML?

In this project, SGML means Study Guide Markup Language. It is a plain-text format used by SGML Viewer to create study notes with interactive questions and visual components. It combines ordinary text, Markdown, HTML, and a small set of SGML-specific tags.

This project-specific SGML is not a complete implementation of the historical Standard Generalized Markup Language, which shares the same abbreviation.

The basic workflow: write the content as text, use syntax markers for special behavior, and select Render SGML to preview it.

What it can contain

  • Study notes using Markdown headings, lists, links, tables, and code.
  • Styled text, badges, pencil-style X marks, hand-marked circles, spoilers, reference links, information panels, and directional arrow connectors.
  • Multiple-choice, fill-in, enumeration, matching, and flashcard activities.
  • Expandable tree graphs and step-by-step timelines.
  • Study-notebook layouts including structured flashcards, callout boxes, checklists, glossaries, revision grids, and Cornell notes.
  • Markdown, HTML, SVG, LaTeX math, isolated HTML containers, and JavaScript-generated source.

2. How to use the viewer

  1. Select New SGML to create a document or Load SGML to open one saved in this browser.
  2. Select Edit Code, then write or paste your SGML. You can upload .sgml, .txt, .md, .docx, or .pdf files with Upload File.
  3. Select Render SGML to display the document. Editing is saved locally as you work.
  4. Use Check All Answers for the document, or use the shared Check Answers button inside a grouped <questionaires> section.
  5. Select Download SGML to save the source to a file.

A first document

# Welcome

This is **my study guide**.

<st bg:#ffff00 col:#111111>Remember this point.</st>

<Choices:
  (What is 2 + 2?)
  [3, 4, 5, 6]
  {[idx:1]}
>

The heading and bold phrase use Markdown. The <st> tag styles a piece of text. The multi-line <Choices> block creates a multiple-choice activity.

Load Sample: loading the sample replaces the current editor content. The viewer asks for confirmation before replacing it.

3. Import DOCX and PDF files

The viewer accepts normal SGML/text sources as well as Word .docx and PDF .pdf files. DOCX files are converted to safe HTML using Mammoth.js, then their import wrapper is temporarily removed so the document content passes through the same top-level SGML and Markdown renderer as a hand-written SGML file. The wrapper and Word styles are restored after rendering. Markdown headings, emphasis, lists, and inline SGML icons are supported in imported DOCX paragraphs, including styled Word paragraphs. PDFs are processed with PDF.js and their selectable text is arranged into HTML paragraphs, with a section for each page.

What gets preserved?

  • DOCX: paragraphs, headings, emphasis, lists, tables, links, and supported embedded images can be kept. Markdown and inline SGML icons in imported document text are passed through the normal top-level renderer.
  • PDF: selectable text and an approximate reading order are preserved; pages remain separated. Complex columns, exact positioning, diagrams, and page artwork may not match the original layout.
  • Built-in SGML syntax such as questionnaire blocks is passed to the existing SGML parser when it appears as recognizable markup in the imported text.
PDF limitation: scanned/image-only PDFs do not contain extractable text. This viewer does not run OCR, so a scanned PDF must first be OCR-processed or converted to a text-based PDF.

Import from a URL

Use ?load= with a URL to a DOCX or PDF, just as you would for a text-based SGML file. The whole URL should be URL-encoded if it contains characters such as &.

?load=https%3A%2F%2Fexample.com%2Freviewer.docx
?load=https%3A%2F%2Fexample.com%2Flecture.pdf
?Queries=https%3A%2F%2Fexample.com%2Flecture.pdf

?Queries=, ?queries=, and ?query= are accepted aliases for ?load=. The remote server must permit browser cross-origin fetching (CORS). Public Google Drive file imports through ?gdrive= are also converted when the downloaded resource is a DOCX or PDF.

Offline behavior

DOCX/PDF conversion libraries are loaded and cached automatically while online. Open the viewer while connected before relying on the first offline conversion. The converted document itself is saved in the browser's local document library, so you can reopen that imported copy offline. The uploaded or fetched document is processed in the browser; it is not sent to a conversion server.

4. General syntax rules

Component attributes

Most SGML components use a colon between an attribute name and its value. Values containing spaces should be wrapped in single or double quotes. For example, title:"Extra information" is one title value, while col:#2563eb is an unquoted color value. Separate attributes with spaces.

<info title:"Extra information" bg:#eef6ff col:#174a73>
  Panel content.
</info>

<arrow target:"diagram-a" head:"arrow" dir:"90" col:"#2563eb" />

Ordinary HTML and SVG keep their normal HTML attribute syntax, such as width="100%", viewBox="0 0 100 100", and style="...". The colon-based form belongs to the SGML components documented below.

Question-block structure

Most questionnaire blocks follow this general shape. The name changes based on the activity, but the question, list, and answer sections use matching delimiters.

<Type:
  (Question or prompt)
  [Choices or items]
  {Correct answer | property:value}
>
<Type:
Selects the built-in activity, such as Choices, Fillin, or Enumeration.
( ... )
Contains the question or prompt text.
[ ... ]
Contains choices, orderable items, or another activity-specific list. Some activities require an empty list, written as [].
{ ... }
Contains the correct answer, answer indexes, or answer settings. The meaning depends on the activity type.
|property:value
Adds an optional setting inside the answer braces, for example |case:false.
>
Closes the questionnaire block.

Whitespace and indentation

For built-in question syntax, spaces, tabs, and newlines between the main sections are flexible. You can put a block on one line or spread it out over several lines. Indentation is for readability; it does not have to match a particular number of spaces.

<Choices:
    (Which value is correct?)
    [10, 20, 30]
    {[idx:1] | case:false}
>

Whitespace that belongs inside a sentence or answer is still part of that text. Markdown also has its own paragraph and line-break behavior. Flexible whitespace does not mean that you should remove the spaces between words.

Literal strings with backticks

Backticks wrap a value that should be treated as literal text. Use them when the value contains punctuation that SGML might otherwise interpret, especially commas, brackets, parentheses, braces, or vertical bars.

<Choices:
  (Which option contains a comma?)
  [Manila, `Washington, D.C.`, Cebu]
  {[idx:1]}
>

The text `Washington, D.C.` is treated as one choice. The comma inside the backticks does not split it into separate choices. Literal strings are also useful when you need to show SGML-looking text, such as `<Choices>`, as content instead of having it parsed as a tag.

Escaping structural characters

Put a backslash before a supported structural character when only that character needs to be literal. Supported escapes include backslash, backtick, vertical bar, square brackets, parentheses, braces, and angle brackets. A comma is a list separator, so wrap a comma-containing value in backticks instead of trying to escape the comma.

\<Choices\> is written as text.
The escaped character \| is a literal vertical bar.
A comma-containing value: `Washington, D.C.`

Use backticks for a longer literal phrase containing a separator; use backslash escaping for an individual supported symbol.

5. Questionnaire syntax

Multiple choice — Choices

<Choices:
  (What does CPU stand for?)
  [Central Processing Unit,
   Control Program Unit,
   Core Power Utility]
  {[idx:0]}
>

The first choice is index 0, the second is index 1, and so on. {[idx:0]} marks the first choice as correct. You may also put the correct answer text inside the braces, but indexes are usually clearer for a choice question.

Fill in the blank — Fillin

<Fillin:
  (What does CPU stand for?)
  []
  {Central Processing Unit | case:false}
>

The learner types an answer. The square brackets remain in the syntax even though they are empty. Multiple accepted answers can be written as a comma-separated list. Use case:true to require matching uppercase and lowercase letters. Use ignoreWhitespace:true to ignore all spaces, tabs, and line breaks while checking an answer; for example, NewYork matches New York. The default is ignoreWhitespace:false.

<Fillin:
  (What is 2 + 2?)
  []
  {4, Four | case:false}
>

Enumeration — Enumeration

Written enumeration asks for a number of text answers:

<Enumeration:
  (Name three primary colors.)
  []
  {Red, Green, Blue | count:3 | case:false | inorder:false}
>

count:3 asks for three entries. case:false makes answer checking case-insensitive. inorder:false allows the accepted answers in any order where the checker supports ordering behavior. ignoreWhitespace:true also makes answer comparison independent of spaces, tabs, and line breaks.

Enumeration can also be an item-ordering task:

<Enumeration:
  (Arrange these values in ascending order.)
  [3, 1, 4, 2]
  {1, 2, 3, 4 | type:order}
>

With type:order, learners reorder the listed items and check the result against the specified order.

Matching — connect

<connect:
  (Match each item to its meaning.)
  [[Array, Queue]
   [Indexed collection, First-in-first-out collection]]
  {answers:
    [[idx:0][idx:0]],
    [[idx:1][idx:1]]
   |shuffle:true}
>

The two nested square-bracket groups contain the left and right columns. Each answer pair has the form [[idx:left][idx:right]]. Indexes start at zero. shuffle:true randomizes the displayed matching items.

Flashcards — flashcard

<flashcard
  (Computer Basics)
  [[What does CPU mean?]
   [What does RAM mean?]]
  {answers:
    [Central Processing Unit,
     Random Access Memory]
   |shuffle:true}
>

The parenthesized section is the deck title. Each nested bracket in the question list is one card prompt. The answers follow answers: inside the braces, in the same order as the prompts. Keep the number of questions equal to the number of answers.

For the question and answer lists, the parser accepts comma-separated values in one bracket pair, repeated bracket groups, or repeated groups inside an outer pair:

<flashcard(Review)[Question 1, Question 2]{answers:[Answer 1, Answer 2]}>
<flashcard(Review)[[Question 1][Question 2]]{answers:[[Answer 1][Answer 2]]}>

A colon after flashcard is optional. Add |shuffle:true inside the answer braces to randomize the deck and show its shuffle control.

Grouped questions — questionaires

Use <questionaires> to put several questions into one activity. Each question uses an explicit type attribute and the child tags q, opt, and ans instead of the parentheses, square brackets, and braces in the compact syntax.

<questionaires requiredCompletion>
  <question type:"Choices">
    <q>What does CPU stand for?</q>
    <opt>Central Processing Unit</opt>
    <opt>Control Program Unit</opt>
    <opt>Core Power Utility</opt>
    <ans>Central Processing Unit</ans>
  </question>

  <question type:"Fillin" caseSensitive>
    <q>What is the exact name of the language?</q>
    <ans>JavaScript</ans>
  </question>

  <question type:"Enumeration" count:3>
    <q>Name three primary colors.</q>
    <ans>Red, Green, Blue</ans>
  </question>
</questionaires>
<question type:"...">
Starts one question. Supported types are Choices, Fillin, and Enumeration.
<q>...</q>
Contains the question prompt, equivalent to the parenthesized section (...).
<opt>...</opt>
Defines one choice or one item, equivalent to an entry in the square-bracket section [...]. Repeat it for multiple entries.
<ans>...</ans>
Contains the accepted answer or answers and optional answer properties, equivalent to the brace section {...}.

Each question is checked by the single button at the bottom of its parent <questionaires> block. The progress display counts questions that have an answer entered or selected; it does not indicate whether those answers are correct. requiredCompletion defaults to the total number of questions, so the shared check button becomes available after every question has been answered. You can set a numeric threshold, such as requiredCompletion:2, to allow checking after any two questions have been answered, or set requiredCompletion:false to remove that minimum.

For an ordering enumeration, use mode:"order" on the <question> tag, add one <opt> for each displayed item, and list the correct sequence in <ans>.

<question type:"Enumeration" mode:"order">
  <q>Arrange these numbers from smallest to largest.</q>
  <opt>3</opt>
  <opt>1</opt>
  <opt>4</opt>
  <opt>2</opt>
  <ans>1, 2, 3, 4</ans>
</question>

Question properties

PropertyValuesMeaning
casetrue / falseWhether answer checking is case-sensitive.
countPositive numberNumber of written enumeration answers requested.
inordertrue / falseWhether an enumeration answer list requires a particular entry order where applicable.
typeorderTurns an enumeration into an ordering activity.
ordertrueLegacy shorthand for type:order in an enumeration answer block.
shuffletrue / falseEnables random ordering/shuffling in matching and flashcard activities.
idxZero-based numberReferences an item by its position: idx:0 is the first item.

6. Built-in formatting and inline components

Styled text — st

<st col:#ff0000 bg:#fff3cd>Important text</st>

col sets the text color and bg sets the background. Color values can use a hexadecimal color beginning with #. You can nest styled text when you want a section to change color temporarily.

The component also accepts fontSize and fontFamily, which become the corresponding CSS properties. display can be set to inline, inline-block, or block to control how the styled span participates in the layout.

<st col:#1d4ed8 fontSize:20px fontFamily:monospace>Larger blue text</st>
<st bg:#fff3cd display:block>A full-width highlighted line</st>
<st col:#ff0000>
  Red outer text
  <st col:#008000>Green inner text</st>
  Back to red outer text
</st>

Inline SVG icons — ico

<icowarning/>  <icosuccess/>  <icoinfo/>  <icoidea/>  <icobook/>
<icowarning scale:[1.5] color:"#d97706" border:"2px #f59e0b"/>
<icobook scale:[32,48] color:"#2563eb" strokeWidth:1.8/>

Inline icons render as bundled SVG, so they do not need external images, icon fonts, or an internet connection. The registry includes status, education, navigation, file, device, finance, media, and common interface symbols. Type <ico in the editor to browse the icon suggestions.

scale:[1.5] applies a uniform multiplier to the default 24-pixel icon size; a value such as scale:[32px] sets an explicit square size. Two values such as scale:[32,48] set width and height independently. Available style parameters are color, fill, strokeWidth, border, opacity, and rotate.

border accepts a width and color in either order, for example border:"2px #f59e0b" or border:"#f59e0b 2px". A single width or color is also accepted; use border:none to disable the border.

Hand-marked circle — encircle

<encircle col:#c62828>Remember this term</encircle>

encircle draws a hand-marked outline around exactly the content between its opening and closing tags. Inline phrases stay in the text flow. When the range contains block Markdown such as a heading, list, quote, separated paragraphs, or display math, SGML places one outline around the complete rendered block range. Text before the opening tag and after the closing tag stays outside. The col attribute chooses the stroke color; when omitted, the viewer uses red.

<encircle col:#c62828>
# Study Guide: SGML
This whole heading and paragraph range is encircled.
$EMC$
</encircle>

Inline Markdown such as **bold** and *italic* is supported inside either kind of encircle.

Badge — badge

<badge col:#1d4ed8 bg:#dbeafe>Important</badge>

badge displays a compact inline label. Use col for its text color and bg for its background color. Both attributes are optional.

Pencil-style mark — x

<x col:#c62828>Incorrect statement</x>

x draws a hand-drawn pencil-style cross over its content. The col attribute changes the mark color; red is used when it is omitted.

Information panel — info

<info title:"Extra information" bg:#eef6ff col:#174a73>
  <p>Optional details appear in a panel when its information button is tapped.</p>
</info>

The viewer inserts an information button. Tapping it opens a panel. title sets the panel heading, while bg and col customize its background and text color. Its content is rendered separately inside the panel, so it does not become ordinary text in the surrounding document.

The panel content supports Markdown and ordinary HTML, questionnaire blocks, and the embedded components handled by the panel renderer, including root, line, encircle, and spoiler. Inline components such as st, badge, x, ref, dictDef, dictWord, arrow, and ico icons can also be used there. A nested info tag does not currently create a second information panel.

Spoiler — spoiler

<spoiler>The answer is 42.</spoiler>

The content is hidden behind an overlay until the reader reveals it. The component behaves inline, so text before and after it remains in the same sentence. The content can include supported inline formatting.

References — ref

<ref id:"topic-a">Jump to the topic</ref>

<ref id:"topic-a" />

The first form creates a link to the matching reference target; the self-closing form can mark a target location. Reuse the same identifier in the link and target.

Dictionary links — dictWord and dictDef

dictDef marks a definition in the document. A matching dictWord becomes a clickable link. Tap it to highlight and scroll to its matching definition; tap the same word again or tap elsewhere to clear the highlight. The word and definition can appear in either order in the source.

<dictWord>Apple</dictWord> is a fruit.

<dictDef>Apple</dictDef> — a round fruit that grows on an apple tree.

Matching uses rendered visible text rather than the original Markdown or SGML source, so a heading, bold text, or an inline SGML element can match the same visible word. The first matching definition is used. Matching is case-insensitive by default. Add these bare boolean attributes to dictDef as needed:

  • caseSensitive requires the same letter case.
  • ignoreWhitespace ignores all whitespace, including spaces, tabs, and newlines. Existing behavior is preserved.
  • ignoreNewline ignores newline characters only.
  • ignoreSpace ignores spaces and tabs only.
  • ignoreSGML compares normalized rendered text, not raw SGML/Markdown markup. For example, HELL, **HELL**, ## HELL, and <span>HELL</span> match as the visible text HELL.
  • allowFirsttextMatching also compares the first text line of a dictWord as an additional term. Formatting on that line is rendered before matching; use ignoreSGML when that term includes Markdown or SGML markup.
<dictWord>
## Apple

Apple Falls
</dictWord>
<dictDef ignoreSGML allowFirsttextMatching>Apple</dictDef>

<dictWord><span>HELL</span></dictWord>
<dictDef ignoreSGML>**HELL**</dictDef>

<dictDef caseSensitive ignoreWhitespace>New York</dictDef>
<dictWord>NewYork</dictWord>

Directional connectors — arrow

<arrow target:"diagram-a" head:"arrow" dir:"90" col:"#2563eb" /> Source note

...content between the markers...

<arrow target:"diagram-a" head:"dot" dir:"270" col:"#2563eb" /> Destination note

An arrow marker is a self-closing inline tag. Markers with the same target value are grouped and connected. At least two markers with the same target are needed to draw a connector. When a group has more than two markers, the viewer links them in nearest-neighbor order.

AttributePurposeValues
targetGroups the markers that should be connected. Reuse the same value for the same connector group.Any shared identifier, such as diagram-a.
headDraws a marker at that endpoint.arrow, dot, or omit it for no head.
dirSets the endpoint direction and guides the connector's approach.An angle in degrees. Common directions: 0 = up, 90 = right, 180 = down, 270 = left. Other numeric angles are accepted too.
colSets the connector and endpoint color.A CSS color, commonly a hexadecimal color.

dir affects more than the arrowhead. The marker is offset in that direction, and the connector curves to approach the endpoint from the opposite side. If the direct path conflicts with the requested direction, the connector bends around the line instead of running through the arrowhead.

7. Tree graphs and timelines

Expandable tree — root and bh

<root> defines the main node. Each nested <bh> creates a branch beneath its parent. The root is visible first; tap a card to expand or collapse its children.

<root>
  <h3>Photosynthesis</h3>
  <p>How plants store energy from light.</p>

  <bh>
    <h4>Light-dependent reactions</h4>
    <p>Light energy helps make ATP and NADPH.</p>

    <bh>
      <strong>Chlorophyll</strong>
      <p>A pigment that absorbs light.</p>
    </bh>
  </bh>

  <bh>
    <h4>Calvin cycle</h4>
    <p>Uses energy to help build sugars.</p>
  </bh>
</root>

Tree cards can contain normal HTML, Markdown-rendered content, styled text, information panels, and supported nested components.

Step-by-step timeline — line and node

<line> creates a vertical timeline. Every <node> is one step. Set title:"..." to choose its visible title. The first step appears initially. Tapping the current step reveals the next; tapping an earlier step moves back to it.

<line>
  <node title:"Plan">
    <p>Define the goal and requirements.</p>
  </node>

  <node title:"Build">
    <p>Implement the planned solution.</p>
  </node>

  <node title:"Test">
    <p>Check expected and edge-case behavior.</p>
  </node>

  <node title:"Release">
    <p>Publish the finished work.</p>
  </node>
</line>

Both tree and timeline components have a resize handle along their bottom edge. Drag it to make the visual area taller or shorter.

8. Study-notebook components

These components add layouts that are awkward to build with ordinary Markdown. They are additive: the original compact <flashcard(...) [...] {answers:[...]}> syntax remains supported.

Structured flashcard deck — flashcards, card, front, and back

<flashcards title="Computer Basics" shuffle="true">
  <card>
    <front>What does CPU mean?</front>
    <back>Central Processing Unit</back>
  </card>
  <card>
    <front>What does RAM mean?</front>
    <back>Random Access Memory</back>
  </card>
</flashcards>

Each <card> contains one <front> question and one <back> answer. Both sides support Markdown and supported embedded SGML such as icons. Set shuffle="true" to enable the existing shuffle control. This new format uses the same flashcard viewer, progress, scoring, and review controls as the legacy syntax.

Notebook callout — notebox

NoteBox icons include subtle CSS motion, such as blinking and looking around for the eye icon. Animations are disabled when reduced motion is enabled on the device.

<notebox type="definition" title="Algorithm">
  A finite sequence of clear steps for solving a problem.
</notebox>

<notebox type="warning" title="Common mistake">
  Do not confuse a variable with its stored value.
</notebox>
<notebox type="important">This point is especially important.</notebox>
<notebox type="reminder">Review this again tomorrow.</notebox>
<notebox type="learn" title="Learning point">A new concept to understand.</notebox>
<notebox type="tip">A useful shortcut or technique.</notebox>
<notebox type="mistake">Avoid this common error.</notebox>
<notebox type="important" title="Keep this" accent="#7c3aed">
  A custom accent color while keeping the preset's default icon.
</notebox>

<notebox type="learn" icon='<svg viewBox="0 0 24 24"><path d="M4 5h16v14H4z" fill="none" stroke="currentColor" stroke-width="2"/></svg>' accent="#ef4444">
  Inline SVG replaces the preset icon.
</notebox>

accent overrides the type's accent color. icon accepts a built-in icon name or quoted inline SVG markup. If either attribute is omitted or empty, the selected type's default is retained. Existing color/col accent aliases remain supported.

There are 126 built-in types. You can use them as the value of type:

General and learning: note, important, reminder, learn, definition, key, idea, insight, concept, overview, summary, takeaway, objective, goal, fact, example, counterexample, analogy, comparison, distinction, background, context, detail, explanation, clarification.

Discussion and study: question, answer, discussion, reflection, think, remember, memorize, review, revision, practice, exercise, quiz, exam, tip, trick, shortcut.

Academic and technical: formula, equation, theorem, principle, rule, law, method, process, steps, procedure, instruction, guide, reference, source, citation, quote, evidence, research, statistic, data, observation, experiment, result, conclusion, hypothesis, assumption.

Planning and status: prerequisite, dependency, requirement, limitation, exception, success, completed, progress, todo, task, action, priority, deadline, schedule, event, resource, follow-up, pending, blocked, optional, required.

Caution and troubleshooting: warning, caution, danger, error, mistake, misconception, pitfall, debug, common-mistake, safety, privacy.

Development and analysis: link, code, syntax, command, output, input, case-study, scenario, pros, cons, advantage, disadvantage, alternative, decision, recommendation, challenge, open-question, personal-note, pro-tip, quick-fact, important-date, new, updated, deprecated, preview, draft, final.

Type names are not limited to the built-in list. An unknown name such as type="field-note" becomes a neutral custom heading. Use title to supply your own heading; use optional accent, bg, and icon attributes to customize its appearance. Empty or omitted title, accent, and icon values retain the selected type defaults. Content supports Markdown, LaTeX, and embedded SGML.

Interactive checklist — checklist and item

<checklist title="Chapter 1 Review">
  <item checked="true">Read the chapter</item>
  <item>Review the definitions</item>
  <item>Practice the examples</item>
</checklist>

Each item is a clickable checkbox. Use checked="true" to mark a task as completed when the page first renders.

Glossary — glossary and term

<glossary title="Important Vocabulary">
  <term name="Algorithm">A step-by-step procedure for solving a problem.</term>
  <term name="Variable">A named place used to store a value.</term>
</glossary>

Each term becomes a clearly separated entry. Definitions support Markdown and embedded components.

Quick revision grid — quickreview and fact

<quickreview title="Before the exam">
  <fact label="FORMULA">E = mc^2</fact>
  <fact label="DEFINITION">A short, clear meaning.</fact>
  <fact label="KEYWORDS">Energy, mass, speed of light.</fact>
</quickreview>

Each <fact> becomes a responsive mini-card. Use it for formulas, dates, definitions, keywords, and memory tricks.

Cornell notes layout — cornell

<cornell title="Cell Structure">
  <cue>Nucleus?
  Mitochondria?</cue>
  <notes>The nucleus stores DNA. Mitochondria release usable energy from food.</notes>
  <summary>Cells contain structures that perform specialized jobs.</summary>
</cornell>

The cue column is for keywords and questions, notes is the main writing area, and summary adds a full-width recap. The columns stack on narrow screens.

Notebook tip: mix these components with ordinary headings, paragraphs, tree graphs, timelines, tables, and diagrams. Using a callout for every paragraph makes the page harder to scan.

8a. Bookmarks and the selection menu

<bookmark title="Chapter 2" subtitle="Cells" type="learn" accent="#2563eb" side="right" userdefined/>

bookmark is a self-closing tag. It marks the place where it is written and shows a tab fixed to the left or right edge of the screen. Only a small arrow peeks in from the edge. Press the arrow to open the card (icon, title with subtitle below, and an X), then press the card to scroll to the tag's position.

AttributeMeaning
title, subtitleText on the card. The title defaults to the type label, or Bookmark.
iconAn icon name or an inline <svg>. Default: Bookmark. An unknown name falls back to the type icon, then Bookmark.
typeAny notebox type. Supplies the default icon, accent color and title.
accentColor of the tab and card, such as #c62828.
sideleft or right (default).
userdefinedAdds the X button.

Dragging

Open a bookmark and drag the card anywhere on screen. When you release it, it snaps to the nearest side edge at the height where you dropped it. Bookmarks may overlap, and the one dragged or opened most recently is on top. The X button sits on the same side as the bookmark: left edge, X on the left; right edge, X on the right.

Editing and removing

Right-click a bookmark (long-press on touch devices) to open a small editor next to it with Title, Subtitle and an Accent color picker (input type="color"). The accent also colors the line that flashes when you jump to the bookmark. Pressing X asks for confirmation in a modal before removing.

Selection menu and saved bookmarks

The browser's own context menu is replaced by a small toolbar that works like the native selection toolbar: it appears above the text when you release the pointer after selecting, and hides as soon as you start selecting again. It offers Copy, Select all, a divider, and Bookmark, and its text cannot be selected. Bookmark creates a userdefined bookmark from the selection with a random accent color from a built-in palette, and saves it, with its title, subtitle, accent and position, in localStorage under sgmlBookmarks. Inputs and the code editor keep the browser's menu.

What is stored: only bookmarks created from the menu. Pressing X on one removes it from storage. Pressing X on a bookmark written in the SGML source only hides it; nothing records the removal, so it returns when the document is rendered again. Edits and dragged positions of source bookmarks are likewise not remembered.

Standalone questions

<question type="choices|fillin|enumeration"> with <q>, <opt> and <ans> also works outside <questionaires>. It renders with its own Check button, like <Choices:()[]{}>.

8b. Procedures, copy/paste, and terminals

sgmlCopy stores SGML and renders nothing; sgmlPaste renders the stored source at each paste location. Use <sgmlHolder id="...">default content</sgmlHolder> inside a copy to define a replaceable value. On each paste, an attribute whose name matches the holder ID replaces its content. Multiple holders can be replaced in one paste, and each paste can provide different values. The inserted SGML is rendered normally.

<sgmlCopy name="example">
  Hello <sgmlHolder id="txth">text here</sgmlHolder>.
</sgmlCopy>

<sgmlPaste name="example" txth="sgmlhere"/>
<sgmlPaste name="example" txth="another value"/>

Procedures — procedure and step

<procedure type="wizard" title="Make a deck">
  Optional introduction text.
  <step title="Pick a topic">Choose one small topic.</step>
  <step title="Write the cards">Question on the front, answer on the back.</step>
</procedure>
  • type="tutorial" (default) is a guide to read through: every step is listed with a collapsible body, a progress bar follows the step you are reading, and Outline (shown from 6 steps) jumps to any step. Collapse all / Expand all fold the whole list. For tick-off tasks use checklist instead.
  • type="wizard" shows one step at a time. A progress bar and a scrollable Steps list (steps you have reached) replace one button per step, so procedures with 100+ steps stay compact. Back / Next / Finish sit under the step and stay on screen.
  • type="solution" hides the steps and reveals them one at a time (or all at once), for worked answers. The Show controls sit under the steps and stay on screen, so long steps never need a scroll back up.

The type is shown as an icon in the header (book, wand, light bulb). Optional attributes: title, accent (any CSS color) and, for tutorials, collapsed="true" to start with every step folded. A step accepts title and any SGML content, including questions. Text before the first step becomes the introduction.

Copy and paste — sgmlCopy and sgmlPaste

<sgmlCopy name="tip">
  <notebox type="tip">Stored once, used many times.</notebox>
</sgmlCopy>

<sgmlPaste name="tip"/>
<sgmlPaste name="tip"/>

sgmlCopy stores its contents and renders nothing. Everything inside is skipped: <js> blocks do not run, questions are not created, and nothing is parsed. sgmlPaste inserts the stored source at that position, so it renders exactly as if you had typed it there, and a pasted <js> block runs at the paste.

  • A paste can appear before its copy. If two copies share a name, the first one wins.
  • A copy can paste another copy. Circular pastes and unknown names show a small red message.
  • A copy inside a backtick literal, an ~~~ ICB fence, a <js> body, or a terminal block is plain text and is not a copy.
  • <sgmlPaste name="x"></sgmlPaste> also works.

Terminals — terminalCode, terminalOutput, and outCode

<terminalCode title="JavaScript" runnable target="demo">
const values = [2, 4, 6];
</terminalCode>

<terminalOutput title="Console" connect="demo" addCode allowInput maxHeight="240px">
  <outCode>
    terminalPrint("Values: " + [2, 4, 6].join(", ") + "\n");
    const name = await terminalInput("Name: ");
    terminalPrint("Hello, " + name + "\n");
  </outCode>
</terminalOutput>

Ordinary terminal contents are literal text: they are not parsed as SGML, Markdown, or JavaScript. outCode is removed from the visible text and executed whenever its terminalOutput appears. It does not require a connected or runnable terminalCode.

Add the bare boolean attribute editable to terminalCode to make the displayed source editable without changing the terminal's normal appearance or behavior. Editable source keeps the same syntax coloring from style, fold controls from folding, line-number gutter, scroll behavior, Copy button, and terminal formatting as a read-only code block. Fold regions are recalculated as the source changes. Edits stay in that rendered instance only; they do not modify the original SGML document, and reloading the document restores the saved source. Use normal text selection and clipboard shortcuts, Enter for a new line, Tab for indentation, and Ctrl+Z / Ctrl+Y for local undo and redo.

The optional suggestion attribute defines custom completions for an editable code block. Each suggestion has three fields: text is the title shown in the list, subtitle is the explanation shown below it, and insert is the source text placed into the editor. Use JSON in a single-quoted SGML attribute so JSON keys and strings can use double quotes. Type part of a suggestion's text to filter the list, or press Ctrl+Space to show all suggestions. Use ArrowUp/ArrowDown to select and Enter or Tab to insert. The special marker $0 in insert is removed and becomes the caret position after insertion. A readable shorthand is also supported, with one suggestion per line in the form text|subtitle|inserted source.

terminalCode and terminalOutput preserve source whitespace, including repeated spaces, tabs, blank lines, and line breaks. Newlines appear as separate terminal lines. Removing an outCode element removes the tag and its executable body only; it does not add replacement whitespace or trim the surrounding terminal text.

<terminalCode editable
  style="#60a5fa function const return; #f59e0b /\x22[^\x22]*\x22/"
  folding="start: [\[{(]; end: [\]})];"
  suggestion='[
    {"text":"log","subtitle":"Write to the console","insert":"console.log($0)"},
    {"text":"warn","subtitle":"Show a warning","insert":"console.warn($0)"}
  ]'>
function greet(name) {
  const message = "Hello " + name;
  console.log(message);
}
</terminalCode>

<terminalCode>
    first    line

\tsecond\tline  
</terminalCode>

<terminalOutput>
    leading spaces
\tindented with a tab

<outCode>terminalPrint("generated");</outCode>
After the script
</terminalOutput>

In the editor, outCode uses the same JavaScript syntax coloring, block folding, and code completions as js. Its completion list also includes the terminal-specific terminalPrint, terminalInput, and getCode built-ins.

  • runnable adds a Run button to terminalCode. target gives that code block its connection name.
  • When connect is present on terminalOutput, its value must match a code block's target. The output starts hidden. Run hides the code and reveals every output connected to that target. Each output gets a Stop button; Stop terminates its running scripts, hides the outputs, and shows the code again.
  • When connect is absent, the output is visible immediately and its outCode runs as soon as the output is created. A connected output runs when Run reveals it. Whenever an output is rendered again or revealed again, its scripts execute again.
  • Each output's scripts run as separate asynchronous IIFEs inside a dedicated Web Worker. They do not share local variables with the page or with another output. Do not run code you do not trust.
  • terminalPrint(value) appends text to that output without adding a newline. Use terminalPrint("first\nsecond") to create a line break. Multiple calls append in order.
  • getCode is a string variable, not a function. It contains the raw text of the connected terminalCode; when the output has no connection, it is an empty string.
  • allowInput enables interactive line input for that output. Call await terminalInput("Prompt: ") to display an editable input at the terminal cursor. The user can type, select, paste, move the caret, and delete text normally; Enter submits the line and the returned Promise resolves to the entered string. The terminal echoes the submitted line. Because worker code is asynchronous, use await just like the example above.
  • maxHeight sets the terminal body's maximum height, such as 240px, 18rem, or 50vh. A plain number is treated as pixels. Both code and output bodies scroll vertically and horizontally when needed. The editor's terminalOutput snippet suggests maxHeight="240px"; it is only a snippet default, not a forced limit.
  • addCode includes the connected source code at the beginning of that output's displayed text. It does not change the value of getCode.
  • Both code and output retain their Copy buttons; the output's Copy button copies its current displayed text, including anything printed by terminalPrint and submitted input.

Existing display attributes remain available: title labels the terminal, accent sets its accent color, and style colors matching words or regex patterns. folding is available on code blocks and supports collapsed line/range/regex settings as described above.

9. Markdown, HTML, SVG, and LaTeX

Markdown support

Ordinary content is rendered through GitHub-flavored Markdown. Common forms include headings, emphasis, links, lists, tables, blockquotes, fenced code, strikethrough, task-list syntax, and automatic line breaks.

# Main heading
## Section heading

**Bold**, *italic*, and [a link](https://example.com).

- First item
- Second item

| Term | Meaning |
|---|---|
| RAM | Random Access Memory |

HTML tags

SGML documents can use standard HTML elements directly, for example <p>, <div>, <span>, headings, lists, tables, images, and media elements. HTML is useful when Markdown is not expressive enough.

<div style="border:1px solid #d9dee5;padding:12px;border-radius:6px">
  <h3>Important definition</h3>
  <p>A <strong>queue</strong> follows FIFO order.</p>
</div>

The viewer removes certain embedded browsing and plugin elements, including ordinary iframe, object, and embed tags. Do not put private information or untrusted code in a study guide.

JavaScript source block — js

The content inside <js> is treated only as JavaScript source. It is evaluated before document parsing and is never itself passed to SGML or Markdown parsers. Only the value returned by the block replaces it; that returned value then passes through the normal SGML, Markdown, HTML, and questionnaire pipeline once.

<js>
  const label = "Generated by JavaScript";
  return `<badge col:#1d4ed8 bg:#dbeafe>${label}</badge>`;
</js>

Use return to provide the content. Returning undefined or null inserts nothing. A returned string can contain other SGML markup, as in the example above. The JavaScript source itself is not displayed or parsed as document content; only the returned value is inserted.

Trust warning: JavaScript in <js> executes in the viewer page context. Only render SGML files containing code from sources you trust. The block is not a sandbox for untrusted JavaScript.

Isolated HTML block (ICB)

A line beginning with three tildes followed by a name starts an isolated HTML container. A line containing only three tildes closes it. This is intended for standalone HTML/SVG examples that need their own scrollable, resizable area.

~~~Mini Example
<div style="padding:16px;background:#eef6ff">
  <h2>An isolated HTML panel</h2>
  <p>This HTML is displayed in its own area.</p>
</div>
~~~

The content runs in a sandboxed iframe separated from the viewer page. Scripts inside the ICB run in that iframe, not in the viewer page. The container starts at a fixed height and can be resized by dragging its bottom handle. Use ICB only when a separate HTML environment is needed; ordinary text and components do not need it.

LaTeX math

MathJax renders inline math with one dollar sign on each side, or display math with double dollar signs.

Inline: $a^2 + b^2 = c^2$

Display:
$$
\frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
$$

10. Mobile editor and smart suggestions

Inside a <js> block, completions include variables and functions declared in that block, arrow-function parameters, JavaScript keywords and globals, and common built-in methods. Member suggestions adapt to recognized values, such as array methods after items. (including join, map, and filter), string methods after string variables, and methods for common browser objects. Suggestions are static and context-aware; they do not execute the code being edited.

The editor uses a real text area for editing. Native Android/mobile selection handles, long-press selection, Select All, copy, cut, and paste come from the browser. Syntax colors and line numbers are display overlays; they do not replace text selection.

  • Type the beginning of a built-in syntax, such as <Choi, to see the Choices suggestion. Tapping it inserts the full question structure and places the cursor at an editable location.
  • Typing a component prefix can suggest templates for encircle, info, badge, x, arrow, spoiler, ref, js, trees, timelines, question blocks, structured flashcards, notebook callouts, checklists, glossaries, quick-review grids, Cornell notes, and the complete ico icon registry.
  • For st, the editor can suggest display values such as inline, inline-block, and block. For arrow, it can suggest the common direction values 0, 90, 180, and 270.
  • Inside a tag, attributes such as title:, bg:, and col: can be suggested for compact SGML components. The XML-style notebook components suggest equals-sign attributes such as title="...", accent="#2563eb", icon="...", and shuffle="true". Color suggestions use hexadecimal values.
  • Question properties can suggest values like true, false, order, counts, and zero-based answer indexes.
  • Use Find, Replace, Go to line, and Suggest for larger documents. The editor also supports indentation, bracket pairing, and syntax-aware templates.

Every attribute enabled for a tag is included in that tag's completion list, even when it has no separate entry in the shared attribute catalogue. Attribute names are matched case-insensitively. Boolean attributes are inserted bare (for example, allowInput or editable); attributes that take values use the appropriate insertion form, such as maxHeight=.

The editor's language profile is in js/editor-language.js. Built-in tag names, attributes, snippets, and context-based suggestions are data-driven, so ordinary syntax additions can be made in that profile without rewriting the editor engine.

While the editor is open, browser/system Back navigation is held to prevent accidental exit. Use Close Editor to leave the editor normally.

11. Automatic resource caching and offline use

There is no manual offline-mode switch. When the network is available, the viewer fetches updated app resources and caches successful responses. If the network is unavailable or a request fails, the service worker serves the last successfully cached app resources when available.

The cache includes the app shell, JavaScript (including the complete inline SVG icon registry), CSS, local libraries, and this documentation page. Open the viewer once while online before relying on offline access, so the browser has a version to use later.

Remember: the viewer, editor, and documentation can load from cache after a successful first visit. Fetching a brand-new remote resource still needs a network connection. Documents already saved in this browser are stored locally.
