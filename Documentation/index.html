1. What is SGML?

In this project, SGML means Study Guide Markup Language. It is a plain-text format used by SGML Viewer to create study notes with interactive questions and visual components. It combines ordinary text, Markdown, HTML, and a small set of SGML-specific tags.

This project-specific SGML is not a complete implementation of the historical Standard Generalized Markup Language, which shares the same abbreviation.

The basic workflow: write the content as text, use syntax markers for special behavior, and select Render SGML to preview it.

What it can contain

  • Study notes using Markdown headings, lists, links, tables, and code.
  • Styled text, hand-marked circles around important words, spoilers, reference links, and expandable information panels.
  • Multiple-choice, fill-in, enumeration, matching, and flashcard activities.
  • Expandable tree graphs and step-by-step timelines.
  • HTML elements, SVG, and LaTeX math, subject to the viewer's handling of embedded content.

2. How to use the viewer

  1. Select New SGML to create a document or Load SGML to open one saved in this browser.
  2. Select Edit Code, then write or paste your SGML. You can upload .sgml, .txt, .md, .docx, or .pdf files with Upload File.
  3. Select Render SGML to display the document. Editing is saved locally as you work.
  4. Use Check All Answers or each question's own check button to mark answers.
  5. Select Download SGML to save the source to a file.

A first document

# Welcome

This is **my study guide**.

<st bg:#ffff00 col:#111111>Remember this point.</st>

<Choices:
  (What is 2 + 2?)
  [3, 4, 5, 6]
  {[idx:1]}
>

The heading and bold phrase use Markdown. The <st> tag styles a piece of text. The multi-line <Choices> block creates a multiple-choice activity.

Load Sample: loading the sample replaces the current editor content. The viewer asks for confirmation before replacing it.

3. Import DOCX and PDF files

The viewer accepts normal SGML/text sources as well as Word .docx and PDF .pdf files. DOCX files are converted to safe HTML using Mammoth.js. PDFs are processed with PDF.js and their selectable text is arranged into HTML paragraphs, with a section for each page.

What gets preserved?

  • DOCX: paragraphs, headings, emphasis, lists, tables, links, and supported embedded images can be kept as HTML.
  • PDF: selectable text and an approximate reading order are preserved; pages remain separated. Complex columns, exact positioning, diagrams, and page artwork may not match the original layout.
  • Built-in SGML syntax such as questionnaire blocks is passed to the existing SGML parser when it appears as recognizable markup in the imported text.
PDF limitation: scanned/image-only PDFs do not contain extractable text. This viewer does not run OCR, so a scanned PDF must first be OCR-processed or converted to a text-based PDF.

Import from a URL

Use ?load= with a URL to a DOCX or PDF, just as you would for a text-based SGML file. The whole URL should be URL-encoded if it contains characters such as &.

?load=https%3A%2F%2Fexample.com%2Freviewer.docx
?load=https%3A%2F%2Fexample.com%2Flecture.pdf
?Queries=https%3A%2F%2Fexample.com%2Flecture.pdf

?Queries=, ?queries=, and ?query= are accepted aliases for ?load=. The remote server must permit browser cross-origin fetching (CORS). Public Google Drive file imports through ?gdrive= are also converted when the downloaded resource is a DOCX or PDF.

Offline behavior

DOCX/PDF conversion libraries are loaded and cached automatically while online. Open the viewer while connected before relying on the first offline conversion. The converted document itself is saved in the browser's local document library, so you can reopen that imported copy offline. The uploaded or fetched document is processed in the browser; it is not sent to a conversion server.

4. General syntax rules

Question-block structure

Most questionnaire blocks follow this general shape. The name changes based on the activity, but the question, list, and answer sections use matching delimiters.

<Type:
  (Question or prompt)
  [Choices or items]
  {Correct answer | property:value}
>
<Type:
Selects the built-in activity, such as Choices, Fillin, or Enumeration.
( ... )
Contains the question or prompt text.
[ ... ]
Contains choices, orderable items, or another activity-specific list. Some activities require an empty list, written as [].
{ ... }
Contains the correct answer, answer indexes, or answer settings. The meaning depends on the activity type.
|property:value
Adds an optional setting inside the answer braces, for example |case:false.
>
Closes the questionnaire block.

Whitespace and indentation

For built-in question syntax, spaces, tabs, and newlines between the main sections are flexible. You can put a block on one line or spread it out over several lines. Indentation is for readability; it does not have to match a particular number of spaces.

<Choices:
    (Which value is correct?)
    [10, 20, 30]
    {[idx:1] | case:false}
>

Whitespace that belongs inside a sentence or answer is still part of that text. Markdown also has its own paragraph and line-break behavior. Flexible whitespace does not mean that you should remove the spaces between words.

Literal strings with backticks

Backticks wrap a value that should be treated as literal text. Use them when the value contains punctuation that SGML might otherwise interpret, especially commas, brackets, parentheses, braces, or vertical bars.

<Choices:
  (Which option contains a comma?)
  [Manila, `Washington, D.C.`, Cebu]
  {[idx:1]}
>

The text `Washington, D.C.` is treated as one choice. The comma inside the backticks does not split it into separate choices. Literal strings are also useful when you need to show SGML-looking text, such as `<Choices>`, as content instead of having it parsed as a tag.

Escaping structural characters

Put a backslash before a supported structural character when only that character needs to be literal. Supported escapes include backslash, backtick, vertical bar, square brackets, parentheses, braces, and angle brackets. A comma is a list separator, so wrap a comma-containing value in backticks instead of trying to escape the comma.

\<Choices\> is written as text.
The escaped character \| is a literal vertical bar.
A comma-containing value: `Washington, D.C.`

Use backticks for a longer literal phrase containing a separator; use backslash escaping for an individual supported symbol.

5. Questionnaire syntax

Multiple choice — Choices

<Choices:
  (What does CPU stand for?)
  [Central Processing Unit,
   Control Program Unit,
   Core Power Utility]
  {[idx:0]}
>

The first choice is index 0, the second is index 1, and so on. {[idx:0]} marks the first choice as correct. You may also put the correct answer text inside the braces, but indexes are usually clearer for a choice question.

Fill in the blank — Fillin

<Fillin:
  (What does CPU stand for?)
  []
  {Central Processing Unit | case:false}
>

The learner types an answer. The square brackets remain in the syntax even though they are empty. Multiple accepted answers can be written as a comma-separated list. Use case:true to require matching uppercase and lowercase letters.

<Fillin:
  (What is 2 + 2?)
  []
  {4, Four | case:false}
>

Enumeration — Enumeration

Written enumeration asks for a number of text answers:

<Enumeration:
  (Name three primary colors.)
  []
  {Red, Green, Blue | count:3 | case:false | inorder:false}
>

count:3 asks for three entries. case:false makes answer checking case-insensitive. inorder:false allows the accepted answers in any order where the checker supports ordering behavior.

Enumeration can also be an item-ordering task:

<Enumeration:
  (Arrange these values in ascending order.)
  [3, 1, 4, 2]
  {1, 2, 3, 4 | type:order}
>

With type:order, learners reorder the listed items and check the result against the specified order.

Matching — connect

<connect:
  (Match each item to its meaning.)
  [[Array, Queue]
   [Indexed collection, First-in-first-out collection]]
  {answers:
    [[idx:0][idx:0]],
    [[idx:1][idx:1]]
   |shuffle:true}
>

The two nested square-bracket groups contain the left and right columns. Each answer pair has the form [[idx:left][idx:right]]. Indexes start at zero. shuffle:true randomizes the displayed matching items.

Flashcards — flashcard

<flashcard
  (Computer Basics)
  [[What does CPU mean?]
   [What does RAM mean?]]
  {answers:
    [Central Processing Unit,
     Random Access Memory]
   |shuffle:true}
>

The parenthesized section is the deck title. Each nested bracket in the question list is one card prompt. The answers follow answers: inside the braces, in the same order as the prompts. Keep the number of questions equal to the number of answers.

Question properties

PropertyValuesMeaning
casetrue / falseWhether answer checking is case-sensitive.
countPositive numberNumber of written enumeration answers requested.
inordertrue / falseWhether an enumeration answer list requires a particular entry order where applicable.
typeorderTurns an enumeration into an ordering activity.
shuffletrue / falseEnables random ordering/shuffling in matching and flashcard activities.
idxZero-based numberReferences an item by its position: idx:0 is the first item.

6. Built-in formatting and inline components

Styled text — st

<st col:#ff0000 bg:#fff3cd>Important text</st>

col sets the text color and bg sets the background. Color values can use a hexadecimal color beginning with #. You can nest styled text when you want a section to change color temporarily.

<st col:#ff0000>
  Red outer text
  <st col:#008000>Green inner text</st>
  Back to red outer text
</st>

Hand-marked circle — encircle

<encircle col:#c62828>Remember this term</encircle>

encircle draws an intentionally irregular, pen-like loop around the content, similar to circling a word on paper. It is not a standard geometric border or a filled circle. The col attribute chooses the stroke color; when omitted, the viewer uses red.

It can contain inline Markdown or HTML, such as <strong> or emphasis, just as other SGML inline components can.

Information panel — info

<info title:"Extra information" bg:#eef6ff col:#174a73>
  <p>Optional details appear in a panel when its information button is tapped.</p>
</info>

The viewer inserts an information button. Tapping it opens a panel. title sets the heading, while bg and col customize its background and text color.

Spoiler — spoiler

<spoiler title:"Reveal answer">The answer is 42.</spoiler>

The content is hidden behind an overlay until the reader reveals it.

References — ref

<ref id:"topic-a">Jump to the topic</ref>

<ref id:"topic-a" />

The first form creates a link to the matching reference target; the self-closing form can mark a target location. Reuse the same identifier in the link and target.

7. Tree graphs and timelines

Expandable tree — root and bh

<root> defines the main node. Each nested <bh> creates a branch beneath its parent. The root is visible first; tap a card to expand or collapse its children.

<root>
  <h3>Photosynthesis</h3>
  <p>How plants store energy from light.</p>

  <bh>
    <h4>Light-dependent reactions</h4>
    <p>Light energy helps make ATP and NADPH.</p>

    <bh>
      <strong>Chlorophyll</strong>
      <p>A pigment that absorbs light.</p>
    </bh>
  </bh>

  <bh>
    <h4>Calvin cycle</h4>
    <p>Uses energy to help build sugars.</p>
  </bh>
</root>

Tree cards can contain normal HTML, Markdown-rendered content, styled text, information panels, and supported nested components.

Step-by-step timeline — line and node

<line> creates a vertical timeline. Every <node> is one step. Set title:"..." to choose its visible title. The first step appears initially. Tapping the current step reveals the next; tapping an earlier step moves back to it.

<line>
  <node title:"Plan">
    <p>Define the goal and requirements.</p>
  </node>

  <node title:"Build">
    <p>Implement the planned solution.</p>
  </node>

  <node title:"Test">
    <p>Check expected and edge-case behavior.</p>
  </node>

  <node title:"Release">
    <p>Publish the finished work.</p>
  </node>
</line>

Both tree and timeline components have a resize handle along their bottom edge. Drag it to make the visual area taller or shorter.

8. Markdown, HTML, SVG, and LaTeX

Markdown support

Ordinary content is rendered through Markdown. Common forms include headings, emphasis, links, lists, tables, blockquotes, and fenced code.

# Main heading
## Section heading

**Bold**, *italic*, and [a link](https://example.com).

- First item
- Second item

| Term | Meaning |
|---|---|
| RAM | Random Access Memory |

HTML tags

SGML documents can use standard HTML elements directly, for example <p>, <div>, <span>, headings, lists, tables, images, and media elements. HTML is useful when Markdown is not expressive enough.

<div style="border:1px solid #d9dee5;padding:12px;border-radius:6px">
  <h3>Important definition</h3>
  <p>A <strong>queue</strong> follows FIFO order.</p>
</div>

The viewer removes certain embedded browsing and plugin elements, including ordinary iframe, object, and embed tags. Do not put private information or untrusted code in a study guide.

Isolated HTML block (ICB)

A line beginning with three tildes followed by a name starts an isolated HTML container. A line containing only three tildes closes it. This is intended for standalone HTML/SVG examples that need their own scrollable, resizable area.

~~~Mini Example
<div style="padding:16px;background:#eef6ff">
  <h2>An isolated HTML panel</h2>
  <p>This HTML is displayed in its own area.</p>
</div>
~~~

The content runs in a sandboxed iframe separated from the viewer page. Use ICB only when a separate HTML environment is needed; ordinary text and components do not need it.

LaTeX math

MathJax renders inline math with one dollar sign on each side, or display math with double dollar signs.

Inline: $a^2 + b^2 = c^2$

Display:
$$
\frac{-b \pm \sqrt{b^2 - 4ac}}{2a}
$$

9. Mobile editor and smart suggestions

The editor uses a real text area for editing. Native Android/mobile selection handles, long-press selection, Select All, copy, cut, and paste come from the browser. Syntax colors and line numbers are display overlays; they do not replace text selection.

  • Type the beginning of a built-in syntax, such as <Choi, to see the Choices suggestion. Tapping it inserts the full question structure and places the cursor at an editable location.
  • Typing <enci suggests the full encircle template.
  • Inside a tag, attributes such as title:, bg:, and col: can be suggested. Color suggestions use hexadecimal values.
  • Question properties can suggest values like true, false, order, counts, and zero-based answer indexes.
  • Use Find, Replace, Go to line, and Suggest for larger documents. The editor also supports indentation, bracket pairing, and syntax-aware templates.

The editor's language profile is in js/editor-language.js. Built-in tag names, attributes, snippets, and context-based suggestions are data-driven, so ordinary syntax additions can be made in that profile without rewriting the editor engine.

While the editor is open, browser/system Back navigation is held to prevent accidental exit. Use Close Editor to leave the editor normally.

10. Automatic resource caching and offline use

There is no manual offline-mode switch. When the network is available, the viewer fetches updated app resources and caches successful responses. If the network is unavailable or a request fails, the service worker serves the last successfully cached app resources when available.

The cache includes the app shell, JavaScript, CSS, local libraries, and this documentation page. Open the viewer once while online before relying on offline access, so the browser has a version to use later.

Remember: the viewer, editor, and documentation can load from cache after a successful first visit. Fetching a brand-new remote resource still needs a network connection. Documents already saved in this browser are stored locally.
